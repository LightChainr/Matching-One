# P334：共同源的局部响应秩

一次固定的定向精度增量已把问题推进到前缀局部：两N的A响应局部行列式均值都稳定为正，积分A对应的两个出生时间中心也给出同样判断。这提供了局部二维条件均值响应存在的数值证据，超出了此前仅有的总体平均响应秩。E及出生间隔的局部行列式目前未分辨。

全部计算在华为HZsCM6的16核环境完成。两次既有数据分析先定位了采样支持与精度瓶颈；随后仅对原3053个双R0前缀，各增加固定64组quartet，总计781568条新suffix，没有增加独立前缀。预算在新读数出现前固定，执行一次后停止，未按结果继续追加。

若每个固定前缀的两源到两几何A条件均值Jacobian都秩不超过1，局部行列式处处为零。上述正的局部均值因此给出该假设之外的数值证据；这一论证使用`E det J(Z)`，不再以`det E J(Z)`替代。它不说明每个前缀的未来响应都为rank2，不是连续场数目或普适性定理，也不排除任意改变潜变量分布形状的标量模型。

平方目标的直接四阶估计仍有较大误差，负值一律保留。其未单独分辨不推翻局部行列式均值的正证据；平方目标主要用于防止把可能的正负抵消误判成rank1。所有指标共用原20批配对协方差，没有把多个端点当成独立票数或计算名义高斯p值。

积分给出明确的机制坐标。令`C=(K1+K2)/2`、`W=K2-K1`，则`integral A=1-2C/(N+1)`，`integral E=1-W/(N+1)`。因此正的积分A局部行列式直接支持两个出生中心的局部二维响应；出生间隔W的对应行列式未分辨。这里在保持即时joint-rank/Euler分布的明确源政策下，以基准分布样本和exact score估计响应导数；新增尾部仍按均匀next-label及suffix law采样，未直接按倾斜后的q_t抽样，也未新增独立prefix总体。

## 初始既有数据结果与追加理由（保留历史）

N325/N425各保留全部20000个原前缀、20个原始批次。每前缀已有8组独立quartet，每组两个独立next-label、每label两条独立suffix。两几何共享每条suffix。旧数据总计128万条suffix，不是本轮新增样本。

第一种估计严格复用原same-class半差。逐批恢复旧S/D转成的J矩阵，最大绝对差为`1.90e-18/2.17e-18`。但只有46/36个前缀的源差分出现非共线quartet对；所有前缀均无可用的四quartet配对。此时行列式平方的`0 ± 0`仅是抽样支持缺失，不能解释为局部rank1。

随后使用主任务在TV2N0X完成的精确标签普查，将每个label的源score写为`H_s=pi_a(L_s-mean_a L_s)`，非joint-safe标签score为0。普查给出精确中心，故`E[H|prefix]=0`，允许不同类别的U,V也用于`(H_U-H_V)(Y_U-Y_V)/2`。这改善相同J估计的效率，没有改变源定义或增加suffix。

## 一次固定的定向精度增量（执行前契约与实际执行）

只对原cell00的1502+1551个前缀，每个新增64组独立quartet，共781568条suffix；不增加前缀总体。预算在新结果出现前固定，不随p值或符号追加。主估计合并原8+新64为72组；另列新64组的条件Monte Carlo结果，它仍共享相同前缀，不是独立总体复现。

直接把原producer的quartet从8改为72会撞流：原`local_id=((prefix_index*8+q)*8+group*4+slot)`。新流固定使用

```
local_id = 0x80000000 | ((prefix_index*64+(q-8))*8+group*4+slot)
q = 8,...,71
key = splitmix64(fork_seed XOR splitmix64((uint64(N)<<32) | local_id))
```

新低位索引始终小于`2^31`；旧起始key命名域无bit31、新域有bit31，N占高32位，两个splitmix64及中间异或都是置换，因此起始key命名域与旧key及不同新key不重叠。这不是不同PRNG种子随机独立性的数学证明；Monte Carlo推断沿用原producer的独立流设计假设。原prefix seed、counter、几何和checkpoint全部不变。

原Mac producer的每640000条尾部耗时16.77/23.99秒。HZ复用逐字节相同的C++rank引擎与原contact实现，按原批次最多16worker完成新781568条尾部：包含首批核验的生成阶段共4.164秒，主分析2.220秒，均首次成功。编译器为GCC10.3.1。首批实际尾部保留在固定预算内，没有额外pilot尾部。

四阶U统计采用代数等价的O(Q)算法。对quartet之间的极化行列式D，设`S=sum_edges D`、`T=sum_edges D²`、`R=sum_vertices(row_sum D)²`，则四阶均值为`(S²+T-R)/(6*C(Q,4))`。T通过每个前缀4×4二阶矩矩阵计算，不逐前缀枚举`72 choose4`。先对任意有限矩阵和原8组逐前缀枚举结果核对后，才应用到64/72组。新/旧/合并三种读数保留同20批joint LOO/factor。

生成记录、40个新增gzip、每批日志与SHA256在`extension/`；最终主结果为`results-extension/score.json`，对应每前缀文件和真实run receipt同目录。`analyze_extension.py`验证输入、流域和代数后复现全部结果；`run_fixed_extension.py`会拒绝覆盖已生成的尾部。没有改动其他团队工作树或进行GitHub写入。

收尾已核验134个输入/新增尾部文件的SHA256、三版共同协方差factor，以及全部781568条新增尾部预算。快速四阶公式与直接枚举差`5.55e-16`；原8组逐前缀统计重建最大差`3.47e-18`。所有产物已取回；确认HZ无活动分析任务后将其恢复Ready，并停止仅属于HZ的本地隧道。最终舰队查询显示五台均为Ready。详见`QA.json`、`REMOTE_RUNS.json`和`MANIFEST_SHA256.tsv`。
