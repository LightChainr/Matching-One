# Research Visibility Atlas

**Snapshot boundary:** 2026-09-01  
**Purpose:** make scientifically substantive work visible even when it is easy to miss from `main`, current Issue bodies, PR titles, or the dominant H4/Q4/Jordan narrative.

This is a navigation and interpretation document. It is **not** the live priority board, a new claim ledger, or a merge/production authorization. Use live Issue labels and the current status/roadmap branch for execution priority. Use the original frozen result artifacts for numerical claims.

## Why this document exists

Matching One has accumulated several kinds of work that ordinary repository browsing systematically underweights:

- completed science reported in Issue comments after the opening body became stale;
- scientifically mature results that remain `open_pr` or `branch_only`;
- closed-unmerged PRs whose result was retained, superseded, or deliberately archived;
- negative results that changed the mechanism class rather than merely “failed”;
- exact controls that rule out an interpretation without providing a new physical model;
- derived views of one random block that are scientifically useful but are **not independent evidence**;
- method/estimator results that determine whether the original observable is computationally reachable;
- semantic corrections that preserve raw data but invalidate an old interpretation.

A reader should therefore never infer research maturity from any one of:

```text
open/closed Issue state
merged/unmerged PR state
README prominence
latest PR number
number of compatible fits
number of exact helper tools
```

The correct unit is a typed evidence chain:

```text
observable/source
  × generator/intervention
  × geometry/context
  × dependency block
  × chronology
  -> finite result / exact theorem / negative result
  -> only then continuum or mechanism interpretation
```

## Reading notation

This atlas uses five integration states:

- **main** — integrated on `main` at the cited snapshot;
- **open_pr** — result exists on an open PR and must not be silently treated as main-integrated;
- **branch_only** — immutable result exists on a research branch but not necessarily in a PR or main;
- **closed_unmerged** — PR closed without merge; the result may still be a retained asset or may be superseded;
- **historical/superseded** — useful for chronology, but a later result changes the scientific interpretation.

It also distinguishes four scientific roles:

- **primary/production** — target acquisition or independent prospective evidence;
- **derived/dependent** — a new view of an existing random block;
- **exact/control** — deterministic finite mathematics or a method/control certificate;
- **method/decision** — estimator, information, governance, or experimental-design result.

These roles must not be added together as evidence votes.

# I. Underexposed physical and statistical research

## 1. Threshold-profile and tail structure is a real production program, not a synthetic side note

**Easy-to-miss reason:** Issue #28's opening language looks like profile tooling, while later comments contain the real large-`N` conclusions.

Substantive result chain:

- production threshold profiles were reconstructed and analyzed beyond synthetic controls;
- one-term Gaussian, `4/3`, and exponential tail models fail strongly on the N265/N290/N325/N425 profile family;
- later K1/K2 and within-tail analyses localize curvature and show that mixing can partially cancel rather than explain it;
- complement-even and resolved odd pieces are useful descriptive coordinates, but they are not two independent leading fields.

**Correct boundary:** this is a failure of several low-complexity tail closures, not a theorem that the asymptotic tail exponent cannot be `4/3`, and not a new independent evidence family for the global H4 signal.

Key route: Issue #28 and the full #1–150 context review captured in Draft #267.

## 2. The orthogonal H4/H12 acquisition actually ran and was non-identifying

**Easy-to-miss reason:** Issue #55 and early protocol PRs still read like a future design.

The frozen orthogonal design was actually acquired at large scale (600M/design, 300 batches in the recovered result chain). The final comparison left both H4 and zero compatible; the H12 amplitude was unresolved.

**Scientific value:** this is not “missing confirmation.” It is a genuine prospective experiment whose information content was insufficient to turn harmonic preference into a standalone nonzero detection.

**Correct boundary:** do not count it as positive global-H4 evidence, and do not reissue it as a missing pilot.

## 9. The rank-one cut-network theorem changes the continuation state object

## 10. Uniform blockade means are provably insufficient; spatial marks survive

The P334 uniform-blockade calculation proves that all mean blockade-dose curves are binomial transforms of the complete clock and obey a semigroup law. Finer mean-dose sampling therefore cannot distinguish two trigger geometries with the same full clock.

A spatial mark can: the exact conditional-response variance depends on the collision probability of the final triggering site, and constructed equal-clock examples have different spatial variances.

**Scientific value:** this is a clean negative information theorem. It says which additional experiment **cannot** help and which mark can carry information that the mean clock loses.

Key route: PR #484 branch result `p334-uniform-blockade-clock-semigroup` and frontier increment e.

# V. The project-level synthesis that follows from the hidden work

The project is no longer well-described as

```text
measure an H4-looking exponent
-> choose a CFT operator
-> refine p_c
```

A more accurate research stack is:

```text
1. exact event/topology/observable semantics
2. sufficient statistics + dependency/covariance control
3. prospective finite-size and shape evidence
4. source/readout overlap and mechanism discrimination
5. generator-specific predictive-state closure
6. statistical/computational reachability of the original observable
7. exact model-class elimination / theorem-facing comparison
8. only then continuum/operator naming or threshold representation
```

Three conceptual distinctions should remain explicit everywhere:

### A. Observable overlap is not harmonic agreement

Two observables may both carry an H4 angular label while having unresolved or different radial/source loadings. P439 is the concrete warning.

### B. State dimension is typed by generator and context

A spatial-translation realization, a Gaussian/dilation transfer, an occupation-growth continuation network and an ordered intervention can have radically different minimal dimensions. P250/P334/P398 provide explicit controls.

### C. Compatibility is not identification

A Jordan-compatible fit, H4-compatible transfer, E4-compatible shape or surviving quartic interval root is only the statement that the declared test has not excluded that model. Identification requires an orthogonal constraint that competitors cannot share.

# VI. How future overview work should read the repository

For any requested “project overview,” “latest status,” or “what remains,” use this order:

1. read `docs/STATUS.md`, but record its snapshot date;
2. read `docs/RESEARCH-MAP.md` and this atlas;
3. inspect live Issue labels for the current P0/P1/P2 lifecycle;
4. inspect the current synthesis/maintenance PR body **and recent comments**;
5. inspect open and closed-unmerged research PRs relevant to the question;
6. use result artifacts, not Issue opening bodies, to decide whether a task actually ran;
7. keep integration state separate from scientific maturity;
8. keep dependency blocks separate from the number of derived scores;
9. record semantic corrections and supersession explicitly;
10. only then summarize the frontier.

If a result is surprising or central, identify at least:

```text
source observable
geometry/context
generator/intervention
raw dependency block
prospective vs post-reveal status
integration state
claim boundary
```

This is the minimum information needed to avoid recreating a shallow “main H4 line plus side programs” view of Matching One.
