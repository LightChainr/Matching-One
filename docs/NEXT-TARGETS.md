This is the fast decision board. It asks:

> Which next output would most change the scientific model space, given the state, source, observer, geometry and acquisition already available?

It is not a queue or permission system. The listed lanes may run in parallel; priority changes attention, not authorization. Lower-ranked or unlisted work is not rejected, locked or required to merge.

## Read lifecycle before priority

One line may have a main theorem, a branch-only consequence, an open-PR result and a proposed production. Use these labels:

```text
main_integrated  canonical shared result
open_pr         inspectable but not merged
branch_only     inspectable remote frontier
hypothesis      proposed mechanism/discriminator
```

An old issue title does not override a completed result. A post-reveal fit is not a new independent block. Several derived coordinates from one histogram remain one dependency group.

Integration, readiness, acquisition and result status are separate. In particular, `branch_only + exact_gate + protocol_frozen + implementation_ready + smoke_only` means acquisition-ready; it is not a production result or an accepted mechanism.

## Proof-carrying lane and Operator Passport

The proof-carrying lane asks whether a **bounded declared class** intersects a frozen typed confidence set. It is not another best-fit ladder. Start with exact semantic zeros, Hankel minors, trace identities and small module relations; P321's module certificates and P250's replay-verified joint-annihilation contradiction are current examples. Escalate only surviving classes to outward interval arithmetic or SOS. Freeze gauge coverage, support bounds, singular-covariance handling and the outer confidence set before reconstruction. A solver failure or numerical SDP relaxation is `inconclusive`, not evidence against the class.

Use the six **Operator Passport coordinates** as a separable research map:

1. `representation` -- state space, sectors and gauge quotient;
2. `finite_algebra` -- generators, relations, radical and exact identities;
3. `propagation` -- transfer/action, positivity or signed status and dependency semantics;
4. `sphere_fusion` -- local fields, junctions and fusion/readout map;
5. `torus_modulus` -- deck/seam characters, geometry and modular response;
6. `microscopic_control` -- exact construction, finite-size controls and acquisition provenance.

No coordinate is a permission gate, and “passport complete” is not a lifecycle status. Teams may fill different coordinates in parallel and should expose tensions rather than collapse them into one operator label.
